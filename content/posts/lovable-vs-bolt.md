## 3 Key Tests

### Test 1: Build a Marketing Landing Page
**Task:** "Build a SaaS landing page with hero, features grid, pricing table, and FAQ." **Lovable:** Polished output on the first pass — professional spacing, modern typography, sensible design choices. Minor prompt iterations to refine copy. **Bolt.new:** Faster first render; design slightly more generic; a few spacing inconsistencies to fix. Both delivered working pages in under 5 minutes.

<div class="verdict-box"><div class="verdict-label">📝 Verdict</div><p class="verdict-text"><strong>Bolt slightly faster; Lovable slightly more polished. Close round.</strong></p></div>

### Test 2: Full-Stack CRUD App
**Task:** "A task manager with user login, projects, and tasks." **Lovable:** Integrated Supabase auth and database automatically — signup, login, and data persistence worked end-to-end without leaving Lovable. **Bolt.new:** Set up a Node.js backend in the WebContainer; auth required more manual steps; persistence needed an external database. Both got there, but Lovable's database integration is significantly smoother.

<div class="verdict-box"><div class="verdict-label">📝 Verdict</div><p class="verdict-text"><strong>Lovable — built-in Supabase makes full-stack apps dramatically easier.</strong></p></div>

### Test 3: Fixing Bugs and Iterating
**Task:** Break something on purpose, then ask the AI to fix it. **Lovable:** Targeted diffs, clear explanations of what changed, rarely broke unrelated parts. Code is readable enough that a developer can jump in later. **Bolt.new:** Fixes worked but occasionally introduced regressions elsewhere; generated code is more tangled. For long-term maintenance, Lovable's output is easier to live with.

<div class="verdict-box"><div class="verdict-label">📝 Verdict</div><p class="verdict-text"><strong>Lovable — cleaner code and more surgical edits win the long game.</strong></p></div>
